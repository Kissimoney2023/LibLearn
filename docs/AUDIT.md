# LibLearn — Repository and Curriculum Audit

Date: 2026-09-17

This is the Phase 1 and Phase 45 deliverable: what the repository actually is,
what works, what does not, and what a Liberia-focused education platform still
needs before it can honestly call itself one.

---

## 1. Architecture as found

| Concern | Actual |
| --- | --- |
| Framework | React 19 + Vite 6, **not** Next.js |
| Language | TypeScript 5.8, `strict: true` |
| Routing | React Router 7, 18 lazy routes; Browser or Hash router via `VITE_HASH_ROUTER` |
| Styling | Tailwind CSS 4 with `@theme` tokens in `src/index.css` |
| State | React context (`AuthContext`, `StudentDataContext`) — no Redux, no query library |
| Backend | Supabase (auth + Postgres). **Optional**: absent env vars → local mode |
| AI | Gemini via `@google/genai`, server-side only |
| Serverless | Netlify Functions v2 (`.mts`) and Vercel functions, both calling one shared handler |
| PWA | Hand-written service worker; icons generated by a dependency-free PNG encoder |
| Package manager | npm |

**The dual-runtime tutor is the best structural decision in the repo.**
`server.ts` (local Express), `netlify/functions/tutor.mts` and `api/ai/tutor.ts`
all delegate to `handleTutorRequest` in `server/tutor.ts`. The safety prompts —
the homework guard and the curriculum disclaimer — exist once. Duplicating them
across three entry points is how they would silently drift apart.

### Visual design

The Stitch design is intact and was preserved: navy header, `#00B140` brand
green reserved for fills with `#006E24` for interactive text (a WCAG contrast
fix made earlier — `#00B140` on white is 2.16:1 and fails AA), card surfaces,
sidebar on desktop, bottom navigation on mobile. Nothing in this pass changed
layout, typography, spacing or colour.

## 2. What works

- Auth in both modes (Supabase and local), route guards, onboarding.
- Learn → topic → lesson → quiz → results, with real progress calculation.
- Exam Coach and a mock exam engine: timer, flagging, navigation, autosave,
  answers masked during the attempt, explanations only after submission.
- Progress from actual attempts — no hardcoded percentages anywhere.
- AI Tutor with grade/subject/topic context, teaching modes and styles.
- Search across subjects, topics and lessons.
- Offline-first: app shell cached, lessons text-first, no video dependency.

## 3. What does not work, in priority order

### 3.1 The deployed site is in local mode — BLOCKER

The screenshot shows *"Running in local mode."* `isSupabaseConfigured` is false
in the deployed bundle, so `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are
not present **at build time** on Netlify.

This is the crux and it is easy to get wrong: `VITE_*` variables are inlined by
Vite during `npm run build`. A variable scoped to *functions* or *runtime* only
is invisible to the build, and the app ships with no Supabase client at all.
**They must carry the `builds` scope.**

Attempts to set them through the Netlify API returned `"Environment variable
upserted"` while a read-back returned `[]`, repeatedly. The write is not
persisting and the cause is not visible from outside. **This one needs a human
in the Netlify dashboard** (see §6).

### 3.2 No verified Liberian curriculum — the honest gap

Covered in §4. This is the real distance between the current app and its
positioning.

### 3.3 Grade coverage was thin — fixed this pass

Seed content covered grades 6, 8 and 10 only, so Grade 11 displayed
*"No topics added yet"* for all six subjects. Grade 11 now has 10 topics, 11
lessons, 34 questions and 11 quizzes. Grades 4, 5, 7, 9 and 12 remain empty.

### 3.4 Gemini free tier caps the tutor at 20 questions/day

Measured directly: `gemini-3.6-flash` on the free tier allows 5 requests/minute
and **20 requests/day**. That is a whole-deployment limit, not per student. The
AI Tutor is therefore not usable in production until billing is enabled on the
Google Cloud project. No code change can avoid this.

### 3.5 Curriculum is bundled, not served

Content lives in `src/data/seed/*.ts` and ships inside the JS bundle. This is
genuinely good for low-bandwidth use — no request, works offline — but it means
**content changes require a redeploy**, and the bundle grows with every lesson.
Migration `0002_curriculum.sql` provides the database side; the read path has
deliberately not been switched over (see §5).

## 4. Curriculum data audit (Phase 45)

### What the UI claims

Grade 11 shows Mathematics, English Language, Biology, Chemistry, Physics and
Civics. **There is no evidence in this repository that this list is the Liberian
national curriculum for Grade 11.** It is a reasonable senior-secondary
selection. That is not the same claim.

### What could be established

Official documents exist and were located:

| Document | Body | Status |
| --- | --- | --- |
| National Curriculum (2011) | Liberia MoE, via UNESCO IBE | Located, **not read** |
| National Curriculum Grades 10–12: Mathematics | Liberia MoE, via UNESDOC | Located, **not read** |
| Education Sector Plan 2022 | Liberia MoE | Located, **not read** |
| WAEC Liberia | WAEC | **Verification required** |

### Why nothing is marked official

The build environment could not open any of them. `ibe.unesco.org`,
`unesdoc.unesco.org`, `moe.gov.lr` and general web fetching are all blocked by
the network egress proxy. Search returns titles and summaries; it does not
return syllabus contents.

Knowing a document exists at a URL is not the same as having read it, and a
topic list cannot be inferred from a title. So every source is recorded as
`located`, never `reviewed`, and **all content is `liblearn` provenance**.

### The WAEC trap, specifically

Most WAEC material findable online describes the **Nigerian or Ghanaian**
examination — "9 subjects", "Civic Education", "trading subject" are Nigerian
conventions. Applying them to Liberia would be a confident, plausible, wrong
answer of exactly the kind that damages students. LibLearn therefore states **no
WASSCE subject requirement, grading scale or entry rule**.

### The standard being applied

A student in Monrovia revising from a topic list we guessed at, sitting an
examination we misdescribed, is worse off than a student who saw an empty
subject and asked their teacher. An empty subject is recoverable. A confidently
wrong syllabus is not.

## 5. Why the curriculum read path was not switched to Supabase

Migration `0002_curriculum.sql` is written and tested. The application still
reads bundled data. This was a deliberate call, not an omission:

1. Supabase is unreachable from this environment (`*.supabase.co` — 403 at the
   proxy), so DB-backed reads could not be executed even once.
2. The deployed app cannot connect to Supabase at all yet (§3.1).
3. Migration 0001 shipped with a bug that only appeared when run against real
   Postgres. Writing a second, larger untestable layer on top invites a repeat.

Switching the read path while unable to run it would mean shipping the entire
Learn experience blind. The bundled path works, is tested, and is better for
low-bandwidth users. **The cutover should happen in one step once §3.1 is fixed
and a real connection can be verified.**

`0002` *was* tested — against local PostgreSQL 16, run as a single transaction
the way the Supabase SQL Editor runs it. That caught a `format('%L')` bug on
policy names that would have aborted the whole migration.

## 6. Recommended order

**Do first — nothing else matters until these are done**

1. **Netlify env vars, with the `builds` scope**, in the dashboard:

   | Key | Scope | Secret |
   | --- | --- | --- |
   | `VITE_SUPABASE_URL` | Builds | No — public |
   | `VITE_SUPABASE_ANON_KEY` | Builds | No — public, RLS governs it |
   | `GEMINI_API_KEY` | Functions (not Builds) | **Yes** |

   Then redeploy and confirm the local-mode banner is gone. The `VITE_` prefix
   is the security boundary: `VITE_*` is public, `GEMINI_API_KEY` must never
   carry it, and the Supabase `service_role` key must never be set here at all.

2. **Run `supabase/migrations/0002_curriculum.sql`** after 0001.
3. **Enable billing on the Gemini project**, or the tutor dies after 20 questions
   a day.

**Then — the actual product work**

4. **Read the Ministry curriculum documents.** This is the highest-value task in
   the project and it needs a person, not a build pipeline. Start with
   *National Curriculum for Grades 10 to 12: Mathematics*. Then mark the source
   `reviewed`, and content can begin claiming `official`.
5. Fill grades 4, 5, 7, 9 and 12.
6. Switch the curriculum read path to Supabase, in one verified step.
7. Glossary, bookmarks and study plans — tables exist, UI does not.

**Later**

8. Teacher/parent/school portals. `UserRole` already carries the roles and RLS
   is structured for them; no migration of existing rows will be needed.
9. Admin content review UI over the existing `review_status` pipeline.

## 7. Technical risks

| Risk | Severity | Note |
| --- | --- | --- |
| Content presented as official curriculum | **High** | Mitigated: DB trigger + validator + UI badges make it structurally hard |
| Anon key exposure | Low | Public by design; RLS is the real control. Verified absent from the bundle: `service_role` |
| Gemini quota exhaustion | **High** | 20/day. Billing required |
| Bundle growth from bundled content | Medium | ~344 kB JS (109 kB gzipped) today; revisit past ~500 kB |
| Env vars not persisting on Netlify | **High** | Blocks all Supabase functionality; needs manual fix |
| Two GitHub remotes | Low | `LibLearn` and `liblearn-liberia-edtech` both receive pushes; consider consolidating |
